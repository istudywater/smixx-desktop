# Smixx Desktop architecture

The three-bus revision preserves the existing native Core Audio engine and Smixx virtual driver. See [product behavior](desktop-mixer-spec.md) and [verification](SIX-SOURCE-VERIFICATION.md).

- **SmixxCore** owns six interchangeable sources, three independent buses, per-bus channel Send/mute/solo/level, shared source controls/effects, bus effects/master, monitor settings, feedback checks, and versioned atomic JSON persistence. Version 1 migration materializes links and backs up all four original mixes before dropping the fourth from active routing.
- **AudioHardware** discovers endpoints by stable UID, captures hardware channels or private application process taps, and opens distinct stereo output endpoints. The private aggregate devices used for taps are capture adapters, not the virtual feeds. Device sample-rate changes rebuild only the affected connection and its AU chain. Permissions remain under macOS control.
- **MixerDSP** captures and processes each source once, then fans it into four SPSC rings (three outgoing buses plus headphones). Each output callback resamples sources to its device clock, applies bus channel controls, sums in float, runs bus processing/master/limiter, and delivers the processed output. The headphone consumer applies its selected channel balance before Send/M/S, independent listening gain, and its own limiter. The fourth callback index denotes the headphone consumer only; there is no fourth exposed driver device. Its independent resampling and listening gain cannot affect application feeds.
- **SMEffects** hosts Apple's N-band EQ, Dynamics Processor, and Peak Limiter in native stereo Audio Units. Instances, buffers, callbacks, and delay compensation are prepared/warmed before HAL starts. Parameters are atomic targets, applied/smoothed by the owning render callback. Dry/wet latency alignment preserves timing across bypass. Native errors silence the affected stage and increment a diagnostic counter. No callback file I/O, logging, heap allocation, or locking is introduced.
- **MixerStore** controls endpoint lifecycle, effect targets, meter polling, persistence, and UI state. Editing selector changes do not change device signatures. Headphone selection changes the six pre-Send channel gains, without changing outgoing routes. Source/endpoint replacement applies mute before rebuilding; producer replacement marks existing ring contents for discard so stale audio cannot become the replacement signal.
- **SwiftUI views** provide six source strips, a headphone fader, and the selected bus strip. The editing selector remains below the bus fader; the headphone selector is in the header immediately left of Settings. Shared source effects/details and bus effects use separate scoped sheets. Setup contains endpoint assignment and headphone listening controls.
- **Driver** retains the existing libASPL-based timeline transport and producer filtering. It exposes Smixx Bus 1 (`org.smixx.audio.meeting`), Bus 2 (`org.smixx.audio.out2`), and Bus 3 (`org.smixx.audio.recording`). Those existing UIDs are intentionally unchanged; their old semantic strings are not new UI role assignments. The retired fourth UID remains prohibited as a mixer input to prevent feedback while an older driver is installed.

## Clock and latency boundaries

Rings use bounded linear resampling plus small occupancy-based clock correction inherited from the prototype. Source and bus compressor stages are each padded to 10 ms at the device's rate, even bypassed; the final limiter has fixed 2 ms lookahead. Device/driver and target ring occupancy add latency. This keeps effect bypass/parameter edits from rebuilding routes or shifting stage latency, but is not a claim of sample-perfect alignment across unrelated capture devices.

Physical latency, drift, Bluetooth behavior, and 60-minute multi-device operation remain live verification gates. Headphones consume source rings on their own physical callback clock; outgoing endpoint availability does not affect listening. No default-device substitution occurs.

## Teams return

Teams route playback feeds the pre-Send headphone mix while suppressing duplicate original playback. Teams Send remains disabled on the meeting bus, enforced by stable application identity. Capture copy can produce duplicate listening regardless of Send status and triggers a warning. Ambiguous hardware loops and duplicated captures receive warnings; application taps do not imply complete isolation of every helper process or hardware loopback.

## Test boundaries

Swift state tests verify routing, migration, and recovery. C signal tests exercise real native AUs and actual mixer functions at several rates, including stereo linkage and monitor isolation. Driver contract tests invoke exact transport callbacks in-process. The updated HAL transport probe is available for installed-device verification but was not run against a replacement driver during this revision. Live Teams/OBS and hardware evidence must remain distinct from these results.
